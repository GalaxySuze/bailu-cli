# 白鹿开发工作流规则

## 核心原则

1. **阶段推进**：严格按照 需求讨论 → 方案文档 → AI Coding → 交付 四阶段推进开发任务
2. **人工节点**：每个阶段的关键决策点需用户确认后方可继续
3. **文档先行**：方案文档产出后才能进入编码阶段
4. **决策记录**：关键技术决策需记录在 ~/.bailu/knowledge-base/projects/{project}/decisions/ 目录下

## 开发规范

### 代码风格
- 遵循项目现有的代码规范和目录结构
- 新文件使用项目已有的命名约定
- 优先复用项目已有的工具函数和组件

### 质量要求
- 所有新增代码需包含必要的错误处理
- 关键逻辑需添加单元测试
- API 变更需更新接口文档
- 不引入安全漏洞（SQL注入、XSS、敏感信息泄露等）

### Git 提交规范
- 提交信息格式：`<type>(<scope>): <description>`
- type: feat / fix / docs / style / refactor / perf / test / chore
- 每次提交聚焦单一变更
- 提交前确保代码通过 lint 和测试

## 工作流触发条件

以下关键词自动触发开发工作流：
- 开发、写代码、实现功能、添加特性
- bug、修复、debug、问题
- 重构、优化、改进
- API、接口、数据库、部署、测试

## 阶段切换规则

- 阶段1→2：用户确认方案方向后
- 阶段2→3：用户确认架构和任务拆分后
- 阶段3→4：所有编码任务完成且用户确认 Review 后
- 阶段4→结束：用户最终验收后
