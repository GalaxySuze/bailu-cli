## 二、各阶段详细差异

### 2.1 主入口（sdd-start / bailu-sdd-start）

#### 公司套件独有功能

1. **版本自动检查与更新**
   - 每次触发都检查远端版本
   - 自动执行 `git pull` + `install.sh`
   - 更新后提示重开对话

2. **回退调整态路由**
   - 支持 `/sdd-revise [编号]` 入口
   - revision-mode 字段族（6 个字段）
   - Revision N 段落追加机制

3. **env-check.json 缓存**
   - 首次完整预检后缓存结果
   - 后续只做轻量检查

4. **专家团模式检测**
   - 检测 `QODER_AGENT_MODE` 环境变量
   - team/expert 模式下禁止执行

#### 白鹿工作流独有功能

1. **Agent 路由表**
   - D1 → planner
   - D2 → architect
   - D3 → code-reviewer
   - D4 → backend-developer / frontend-developer
   - D5 → code-reviewer
   - D6 → test-engineer
   - D7 → code-reviewer

2. **流程预览能力**
   - D1 完成后输出完整路线图
   - 展示各阶段产出和模式说明

3. **品牌信息与兼容入口**
   - `/bailu-dev` 兼容入口
   - SDD 不可用时 fallback 到原生四阶段工作流

4. **阶段产物索引**
   - sdd-context.md 增加 `阶段产物索引` 字段
   - 每个阶段完成后追加产物路径

### 2.2 D1 任务分配与评估

#### 公司套件

- 支持执行模式判断（轻量模式 / OpenSpec 模式）
- 轻量模式下 D1 完成后直接跳到 D4
- OpenSpec 模式下 D1 完成后推进到 D2

#### 白鹿工作流

- 增加 **代码扫描辅助规模判定**（Step 3）
  - 自动扫描项目文件
  - 生成规模判定报告
  - 根据文件数和接口变更数判定需求规模

- 增加 **OpenSpec 使用时机判断**（Step 6）
  - 小需求：不生成 OpenSpec
  - 中等需求：推荐生成 tasks.md
  - 大需求：必须生成完整 OpenSpec

- allowed-tools 增加 `Glob` 和 `Grep`

#### 差异总结

| 功能 | 公司套件 | 白鹿工作流 |
|------|---------|-----------|
| 代码扫描 | ❌ | ✅ |

| OpenSpec 时机判断 | ❌ | ✅ |

## 三、同步更新方案

### 3.1 方案概述

由于白鹿工作流在移植时做了大量改造（删除回退调整态、增加 Agent 路由、修改配置路径等），**不建议直接覆盖同步**。推荐采用 **选择性同步** 策略。

### 3.2 同步策略

#### 策略一：选择性同步（推荐）

**适用场景**：保留白鹿工作流的改造，只同步公司套件的增量更新。

**操作步骤**：

1. **建立差异跟踪清单**
   ```bash
   # 在白鹿工作流仓库中创建同步跟踪文件
   touch docs/sdd-sync-tracking.md
   ```

2. **定期检查公司套件更新**
   ```bash
   cd ~/Code/GitHub/semir-devops-skills
   git log --oneline --since="上次同步日期"
   ```

3. **人工评估每个更新**
   - 功能增强类：评估是否需要同步到白鹿
   - Bug 修复类：优先同步
   - 回退调整态相关：跳过（白鹿不支持）
   - 配置路径相关：适配后同步

4. **选择性合并**
   ```bash
   # 示例：同步某个具体文件的更新
   cd ~/Code/AIAgent/bailu-cli
   
   # 对比具体文件差异
   diff ~/Code/GitHub/semir-devops-skills/D1-02-sdd-planning/SKILL.md \
        packages/cli/assets/skills-zh/bailu-sdd-d1-planning/SKILL.md
   ```

#### 策略二：维护同步适配层

**适用场景**：希望自动化同步，但需要保留白鹿改造。

**操作步骤**：

1. **创建适配脚本**
   ```bash
   # packages/cli/scripts/sync-sdd.sh
   #!/bin/bash
   
   SOURCE_DIR="$HOME/Code/GitHub/semir-devops-skills"
   TARGET_DIR="$HOME/Code/AIAgent/bailu-cli/packages/cli/assets/skills-zh"
   
   # 定义同步映射关系
   declare -A SYNC_MAP=(
     ["D1-02-sdd-planning"]="bailu-sdd-d1-planning"
     ["D2-02-sdd-tech-design"]="bailu-sdd-d2-tech-design"
     # ... 其他映射
   )
   
   # 同步逻辑（排除回退调整态相关内容）
   for src in "${!SYNC_MAP[@]}"; do
     tgt="${SYNC_MAP[$src]}"
     echo "同步 $src → $tgt"
     # 这里需要人工审查，不能直接覆盖
   done
   ```

2. **建立同步检查清单**
   - [ ] 检查公司套件是否有新版本
   - [ ] 对比各阶段 SKILL.md 差异
   - [ ] 评估是否需要同步
   - [ ] 适配白鹿特有功能（Agent 路由等）
   - [ ] 测试同步后的功能

#### 策略三：双向同步（长期方案）

**适用场景**：希望将白鹿改造反哺回公司套件。

**操作步骤**：

1. **将白鹿改造提交到公司套件**
   - Agent 路由机制
   - 流程预览能力
   - 多平台 Git CLI 支持

2. **建立统一的上游仓库**
   - 公司套件和白鹿工作流共享同一套 SDD 核心
   - 通过配置或插件机制支持不同平台

## 四、总结

### 4.1 核心差异

1. **回退调整态**：公司套件支持，白鹿已删除
2. **Agent 路由**：白鹿独有，公司套件无
3. **配置路径**：`.semir-devops-skills` vs `.bailu`
4. **Git 平台**：公司套件固定阿里云效，白鹿支持多平台

### 4.2 同步建议

**推荐采用策略一（选择性同步）**，原因：

1. 白鹿工作流已做大量改造，直接覆盖会丢失改造
2. 回退调整态功能在白鹿中不需要，同步无意义
3. Agent 路由是白鹿独有功能，需要保留
4. 选择性同步可以控制更新风险

### 4.3 后续行动

1. 建立同步跟踪机制
2. 定期检查公司套件更新（建议每月一次）
3. 评估每个更新是否需要同步
4. 测试同步后的功能
5. 更新版本号和同步日志
